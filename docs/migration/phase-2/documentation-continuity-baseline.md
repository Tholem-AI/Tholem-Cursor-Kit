# Phase 2 Documentation Continuity Baseline

## Purpose

Establish default-on continuity behavior so project context persists through deterministic documentation updates, with or without Generate Memories.

## Baseline Principle

Documentation continuity is mandatory baseline behavior.
Generate Memories is additive and does not replace documentation hygiene requirements.

## Minimum Required Continuity Artifacts

- `ROADMAP.md` lifecycle updates for significant work changes.
- focused documentation updates for decisions, assumptions, and handoff context.
- concise completion summaries for major workflow phases.

## Trigger Points

Continuity updates are required after:
- bootstrap initialization or re-bootstrap,
- major policy/rule changes,
- significant architecture or workflow updates,
- completed milestone or phase handoff.

## Required Update Content

Each continuity update should include:
- what changed,
- why it changed,
- impact on next actions,
- owner or responsible workstream.

## Non-Goals

- Narrative duplication across multiple docs.
- Large historical logs embedded in runtime artifacts.
- Reliance on optional memory systems for required project state.

## Validation Evidence

Validation passes when:
- continuity update checkpoints are defined,
- roadmap and docs update rules are explicit,
- Generate Memories is documented as additive behavior only.

## Ownership

- Primary Owner: Documentation and Examples
- Policy Approver: Runtime Core
- Governance Approver: Migration Governance
