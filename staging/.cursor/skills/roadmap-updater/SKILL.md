# roadmap-updater

Maintain `ROADMAP.md` as the canonical deterministic task lifecycle artifact.

## When to use

- Use when approved work must be translated into roadmap checkpoints or status updates.

## Required behavior

1. Convert approved work into explicit roadmap checkpoints.
2. Update status progression without losing prior decision context.
3. Keep entries concise, actionable, and traceable to implementation evidence.
4. Flag contradictions between roadmap state and manifest/runtime state.

## Guardrails

- Avoid creating duplicate task systems.
- Preserve chronological auditability of updates.
- Escalate unresolved blockers instead of masking them.
